# 部署到服务器

**可以部署。实测常驻内存约 110 MB，512 MB 的 VPS 就够。**

但**必须先解决鉴权** —— 看下一节。跳过它直接暴露到公网，等于把账户控制权交给所有人。

---

## ⚠️ 部署前必读：这个项目没有鉴权

代码里自己就警告了（`server.mjs:94`）：

```js
console.log(`  ⚠ Listening on ${host} — reachable from your local network. No auth.`);
```

**11 个会改状态的端点，匿名可调：**

| 端点 | 后果 |
|---|---|
| `POST /api/paper/create` | 建模拟盘会话 |
| `POST /api/paper/:id/order` | **下单** |
| `POST /api/paper/:id/cancel` | 撤单 |
| `POST /api/paper/:id/auto` | 开启/关闭自动交易 |
| `POST /api/paper/:id/decide` | 触发一次决策 |
| `POST /api/paper/:id/risk` | **改风控参数**（把止损设成 99% 就永远不止损） |
| `POST /api/paper/:id/reset` | 重置账户 |
| `DELETE /api/paper/:id` | 删会话 |
| `POST /api/ai/settings` | **写入 AI 配置（含 API 密钥）** |
| `POST /api/ai/test` | 用你的密钥发一次真实请求（会消耗额度） |
| `POST /api/optimize` | 触发参数搜索（CPU 吃满） |

虽然只是**模拟盘**（不会真的下单），但：
- AI 密钥存在服务端，`POST /api/ai/settings` 能覆盖它
- `POST /api/ai/test` 能用你的密钥发请求，**消耗你的额度**
- `POST /api/optimize` 能让服务器 CPU 跑满

**所以：不允许直接 `0.0.0.0` + 公网 IP 暴露。**

---

## 三种部署方式（按推荐度）

### 方式一：只绑回环 + SSH 隧道（最安全，推荐）

服务保持默认只绑 `127.0.0.1`，通过 SSH 隧道访问。**不用改任何配置，不用加鉴权。**

```bash
# 服务器上
node server.mjs &          # 蜘蛛 UI  127.0.0.1:4317
node quant/server.mjs &    # 量化看板 127.0.0.1:4400

# 你本机
ssh -N -L 4400:127.0.0.1:4400 -L 4317:127.0.0.1:4317 user@你的服务器
# 然后浏览器开 http://127.0.0.1:4400/
```

| 优点 | 缺点 |
|---|---|
| 零鉴权风险 —— 服务根本没暴露 | 每次要开隧道 |
| 不用改代码、不用配 nginx | 手机等不方便用 |

**适合：只有你自己用。**

---

### 方式二：Nginx 反代 + Basic Auth（要公开访问就用这个）

服务绑 `0.0.0.0`，但只在 Nginx 后面，Nginx 加一层密码。

```bash
# 1) 生成密码文件
sudo apt install apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd 你的用户名

# 2) Nginx 配置 /etc/nginx/sites-available/quant
server {
    listen 80;
    server_name your-domain.com;

    auth_basic           "quant-spider";
    auth_basic_user_file /etc/nginx/.htpasswd;

    # 量化看板
    location / {
        proxy_pass http://127.0.0.1:4400;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 180s;      # 优化器可能要跑很久
    }

    # 蜘蛛 UI（可选）
    location /spider/ {
        proxy_pass http://127.0.0.1:4317/;
    }
}

# 3) 启用 + 重载
sudo ln -s /etc/nginx/sites-available/quant /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**注意**：这样服务本身仍然只听 `127.0.0.1`（默认值就够），**不需要改绑定地址**。Nginx 从本机转发进来。

再配上 HTTPS（`certbot --nginx`）更好 —— Basic Auth 是明文传输的。

**适合：要给几个人用。**

### 方式三：Docker（配置已写好，但**我没验证过**）

```bash
git clone https://github.com/youdoufu-shuai/quant-spider.git
cd quant-spider
docker compose up -d --build
```

**⚠️ 诚实说明**：`Dockerfile` / `docker-compose.yml` 写好了，但**我本机没有 docker，从未跑过**。只有 YAML 结构校验过。第一次用请留意：

- 它用 `network_mode: host`（因为两个服务默认硬编码绑 `127.0.0.1`，Docker 端口转发进不去容器 loopback）
- `network_mode: host` 在 **Linux 的 Docker Engine 上可用**；Docker Desktop（Windows/macOS）默认不支持
- 镜像里已经把 `QUANT_PYTHON` 设成 `/usr/bin/python3`

如果 compose 起不来，直接用方式一或方式二（裸机跑，更简单）。

## 服务器要求

### 内存：512 MB 够用

| 项 | 实测 |
|---|---|
| 两个服务常驻 | **110 MB**（冷启动 109.8 / 空闲 106.8） |
| 连续用一阵后 | 约 130 MB（有请求缓存） |
| 每次请求 spawn 的 Python 进程 | 峰值 **36~47 MB**，算完即退 |
| 精简 Linux 容器空载 | 50~150 MB |

**512 MB 的 VPS 跑得动，1 GB 舒服。** 但注意：

> 上面只是**应用**占用。Windows Server 空载就要 1.5~2 GB ——
> **512 MB 只能是 Linux。**

详细的测量方法和数据见 [部署内存占用](部署内存占用.md)。

### 系统

- **Linux**（推荐 Debian/Ubuntu）
- **Python 3.12+** 和 **numpy** —— 唯一依赖
- **Node.js 20+**
- 不需要数据库、不需要 Redis

```bash
# Debian/Ubuntu
sudo apt update
sudo apt install -y python3 python3-numpy nodejs git
python3 -c "import numpy; print('numpy', numpy.__version__)"   # 验证
node --version                                                  # 要 >= 20
```

⚠️ **Debian/Ubuntu 自带的 nodejs 常常低于 20**，那样跑不起来。用 NodeSource 装：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

### 网络

服务要能访问：`hq.sinajs.cn`（A 股）、`data-api.binance.vision`（加密）。
如果服务器在国内且访问不了币安，加密功能会降级 —— A 股不受影响。

## 裸机部署步骤

```bash
git clone https://github.com/youdoufu-shuai/quant-spider.git
cd quant-spider
pip3 install numpy          # 通常 apt install python3-numpy 更快

# 验证一切正常（不联网也能跑，约 10 秒）
node tools/run-tests.mjs --offline
# 期望：9 套 Python 自检 / 1349 断言 + Node 44 通过

# 启动（用 systemd 管起来，见下）
node quant/server.mjs
```

### systemd 服务（开机自启 + 崩溃重拉）

`/etc/systemd/system/quant-spider.service`：

```ini
[Unit]
Description=quant-spider 量化看板
After=network-online.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/home/你的用户名/quant-spider
Environment=QUANT_PORT=4400
Environment=QUANT_HOST=127.0.0.1
Environment=QUANT_PYTHON=/usr/bin/python3
ExecStart=/usr/bin/node quant/server.mjs
Restart=on-failure
RestartSec=3
# 限制内存，防止异常时吃光机器
MemoryMax=512M

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now quant-spider
sudo systemctl status quant-spider
journalctl -u quant-spider -f        # 看日志
```

### 只保留「假设已持仓」不需要的东西

如果只是自己看行情和分析，**不用跑蜘蛛 UI**（省 55 MB）：

```bash
node quant/server.mjs      # 只跑量化看板
```

蜘蛛 UI（`server.mjs`，4317）是上游那个动画查看器，和量化功能无关。

## ⚠️ 安全边界（这个项目自己的）

- **`quant/state/` 绝对不能公开** —— 里面有 `ai-config.json`（API 密钥）、
  `paper-sessions.json`（账户状态）。已在 `.gitignore` 里，但**部署时注意别把它放进 Web 根目录**
- **服务没有鉴权** —— 见本文开头
- **`server.mjs` 有个前缀检查理论上可绕过** —— 已知问题，别把服务暴露到不受信网络
- **不要用 root 跑** —— systemd 配置里指定了 `User=`

## 一句话

| 你的情况 | 怎么做 |
|---|---|
| 只有你自己用 | **方式一**（SSH 隧道），零风险 |
| 要给几个人用 | **方式二**（Nginx + Basic Auth + HTTPS） |
| 想用 Docker | 方式三，但**它没被验证过**，出问题回退到方式一/二 |

**别做的：直接 `QUANT_HOST=0.0.0.0` 暴露到公网。**
