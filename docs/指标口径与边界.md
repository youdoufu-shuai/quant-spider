# 指标口径与已知边界

这篇记录的是**经过验证的口径**和**已知的行为边界**。
写它的原因：24 个指标里，很多错误不会抛异常，只会让数字悄悄算错
（比如把全 NaN 当横盘、把预热期填成人造中值），
而下游的打分模型会把这些"看起来正常的假值"当成真实证据。

以下是独立测试套件（`quant/tests/`，808 条断言）逐点手算核对过的结论。

---

## 一、已核对的口径

| 指标 | 口径 | 怎么核的 |
|---|---|---|
| **Wilder 平滑**（RSI/ATR/ADX） | α = 1/n | 核到 Wilder 原书首个 RSI = **70.464135**，且与独立实现逐点 0 偏差 |
| **EMA** | α = 2/(n+1) | 手算递推比对 |
| **布林带** | σ 用 **ddof=0**（总体标准差） | 常数序列：ddof=0 → σ=2.0；ddof=1 → 2.13808 |
| **SMA** | 窗口内有效值 ≥ 75% 才输出 | 边界用例：need=3/4 |
| **MACD** | DIF = EMA12−EMA26；DEA = EMA(DIF,9)；柱 = (DIF−DEA)×2 | 与行情软件口径一致 |
| **ADX** | Wilder 平滑，预热 26 根 | — |
| **KDJ** | SMA(d) 版本（非国内 1/3 平滑） | 见下方"行为边界" |

**回测口径**：强制**下一根开盘**成交（无未来函数）；成本拖累是**实测**（零成本重跑一遍取差），不是估算。

## 二、已知行为边界（不是缺陷，但下游必须知道）

### 1. `adx()` 在完全水平的价格上返回整条 NaN

+DI = −DI = 0 → denom = 0 → DX = NaN → 整条 NaN。
**这是对的**（没有方向就没有趋势强度），但下游不能把 NaN 当 0 用。
预热 26 根。

### 2. `wilder()` 的种子按位置切片，中间混入 NaN 会毒化整条

种子取 `mean(values[start:start+n])`。切片里有 NaN → 种子 NaN → 整条全 NaN
（即使后面有 ≥n 个有效值）。
真实调用链（RSI/ATR/ADX）的输入是"前导 NaN + 后缀有效"，不会触发。
但**任意中间带 NaN 的输入**会。写新指标时注意。

### 3. `ema()` 首值为 NaN 则整条 NaN

递推不可恢复。这是 EMA 的定义决定的，不是 bug。

### 4. `stochastic()` 预热期返回 NaN（已修）

原实现预热期填 **50**（因为 `NaN > NaN` 为 False 走了"否则"分支），
导致 K 从下标 2 就有值、前 13 根的人造 50 被当真实读数。
**2026-10-16 已修**：现在要求 hh/ll 有限且 hh > ll 才计算，
数据有效但无波动（hh == ll）仍返回真实中性 50。
实测 K 的第一个有效下标从 2 变成 **15**。

### 5. `macd_trend` 在 2 根 K 线上就会给买入信号

EMA 无预热期，DIF 从第 0 根就有值，所以 2 根数据就可能 DIF > DEA。
其余 4 个策略都要等 RSI/ADX/布林/唐奇安预热，短序列上是空仓。
**影响**：短序列下只有 momentum 因子有值，`total_w` 可能越过 0.25 阈值
→ 数据不足时打分模型**不提供保护**。
用的时候确保 K 线根数 ≥ 100。

### 6. `IndicatorSet.at("close", i)` 恒为 None

`values` 字典里**只有 27 个计算出来的指标**，没有 close/open/high/low/volume ——
它们是原始行情，存在 `series.bars[i]` 里。
`autotrader._val()` 已经处理了这个回落，但新写的代码容易踩。

### 7. 分档阈值的浮点边界

`0.95 - 0.80 = 0.1499999999999999 < 0.15` → 判为"不动"，
但理由文本用 `%.0f%%` 显示为「15%」，肉眼看着与阈值相同。
**方向是安全的**（偏保守），仅记录。

### 8. `Viewport.on` 兼容两种签名（已修）

`on(fn)` 与 `on(name, fn)` 都支持。
原实现只接受 `on(fn)`，而调用方按 `Chart` 的风格传 `(name, fn)` ——
字符串被当回调收下、真回调被丢弃，**静默失效**。

## 三、NaN 相关的两条铁律

这个项目里"NaN 与 0 比较恒为 False"踩了**两次**，而且表现完全不同：

| 位置 | 写法 | 表现 |
|---|---|---|
| `paper.py` | `if px <= 0:` | NaN **漏过**保护 → `math.floor(NaN)` **崩溃** |
| `backtest.py` | `if px > 0:` | NaN **恰好被挡住** → 静默跳过（碰巧正确） |

所以：

```python
# ❌ 不要这样 —— NaN 会漏过去
if px <= 0: reject()

# ✅ 要这样 —— NaN 得到 True，被正确拦住
if not (px > 0): reject()
```

**同理**：任何"检查是否有效"的地方都用正向判断再取反，
不要用负向判断。`np.where(cond, a, b)` 里的 `cond` 遇到 NaN 也是 False，
会静默走 `b` 分支 —— `stochastic` 的预热造假就是这么来的。

## 四、坏数据的处理策略

`run_backtest` 在入口检查收盘价：

- **坏 K 线 ≥ 3 根 且 占比 > 5%** → 抛 `ValueError`
  （双条件：只用比例会让"4 根里 1 根坏"的短序列被误判成 25%；
  只用绝对数会放过长序列的系统性坏数据）
- **少量坏 K 线** → 权益按前一根结转 + `RuntimeWarning`

另外 `len(bars) < 3` 直接拒绝 —— 少于 3 根算不出任何有意义的东西。

为什么不全拒也不全忍：真实行情里偶发一两根脏数据（停牌、采集错误）很常见，
为它拒绝整个序列太粗暴；但**大片**数据坏掉就是数据源出问题了，
必须明确报错，而不是给一堆看着像样的数字。

## 五、怎么自己验证

```bash
python quant/tests/run.py              # 808 断言 / 209 用例，约 1 秒
python quant/tests/run.py --bench      # 含性能基准（5000 根）
python quant/tests/test_indicators.py  # 单文件也能跑
```

性能参考（构造数据，不联网）：

| 规模 | `compute()` | 5 个策略 | `run_backtest()`×5 | `PaperTrader` |
|---|---|---|---|---|
| 500 根 | 42 ms | 14 ms | 116 ms | 11 ms |
| 5000 根 | 441 ms | 128 ms | 867 ms | 122 ms |

`compute()` 单根均摊 84~102 µs —— **线性，无 O(n²)**。
测试里针对 10 个指标函数 + compute + backtest + paper 做了"每根耗时比 < 3~4"的回归护栏。

注意 `run_backtest` 每次调用会跑**两遍**（零成本重跑以实测 cost_drag），
×5 策略 = 10 遍，867 ms 里约一半是这个。这是**有意的设计**，不是重复计算 bug。
