# 模拟盘（纸上交易）说明

> 打开：**http://127.0.0.1:4400/paper.html**
> 也可以从量化看板顶部导航点「模拟盘 →」。

---

## 先区分两个东西

项目里有两个「模拟盘」，职责完全不同：

| | `quant/paper.py` | `quant/paper_live.py` |
|---|---|---|
| 是什么 | **离线回放器** | **交互式模拟盘** |
| 做什么 | 拿一段历史 K 线一次性跑完，输出最终账户 | 长驻会话，行情推到哪跟到哪，可随时下单 |
| 有下单接口吗 | ❌ 没有 | ✅ 有 |
| 账户会变吗 | 跑完就固定 | ✅ 随行情与成交持续变化 |
| 状态保留 | 不保留 | ✅ 存本地 JSON，重启不丢 |
| 用途 | 回测的另一种呈现 | 真正「用」模拟盘 |

**你之前看到的是左边那个** —— 一个静态结果面板。这次实现的是右边这个。

## 功能清单

### 账户管理
- 建账户：选市场 / **标的（可搜索）** / 粒度 / 初始资金，创建时自动拉一次**真实行情**
- 多账户：最多 **8 个**，可同时开 A 股和加密的对比
- 删除、重置（重置保留初始资金设置，清空成交与日志）
- **持久化**：状态写 `quant/state/paper-sessions.json`，重启 Node 或 Python 都不丢
- 账户写进 URL hash（`paper.html#<id>`），可直接收藏某个账户

### 标的：8265 只 A 股 + 511 个加密对

原来每个市场只写死 8 个标的，想买「宁德时代」得改代码。现在：

| 市场 | 数量 | 来源 |
|---|---|---|
| **A 股 / 指数 / ETF** | **8265** | 新浪批量枚举 |
| **加密货币** | **511** | Binance exchangeInfo（USDT 现货对） |

**怎么选**：
- **快捷标签** —— 常用的 36 个 A 股（指数 + 权重蓝筹 + 主流 ETF）和 30 个币种，点一下就选
- **搜索框** —— 输代码或中文名，支持模糊匹配：
  - `宁德` → 宁德时代
  - `300750` → 宁德时代
  - `上证` → 上证指数 / 上证380 / 上证180 …
  - `芯片` → 芯片ETF国泰 / 芯片ETF易方达 …
  - `ada` → 艾达币 ADAUSDT
  - `比特币` → BTCUSDT

**为什么不把 8265 项塞进下拉框**：实测 DOM 里放几千个 `<option>` 后打开下拉要卡好几秒。
所以常用项做成标签、其余走服务端搜索。

**枚举耗时**：A 股全量枚举需要 **98 秒**（51997 个候选代码，新浪批量查询），
结果缓存 12 小时。第一次用会等一会儿，之后是 14ms。

### 下单
| 类型 | 行为 | 何时用 |
|---|---|---|
| **下一根开盘**（默认） | 下单后等下一根 K 线开盘成交 | 与回测口径一致，**没有未来函数** |
| **立即市价** | 按当前价立刻成交（含滑点） | 想马上看到结果时用 |

> ⚠️ 市价单有**同一根内的前视**：如果你看着已确定的收盘价下单，
> 等于用了当时还拿不到的信息。所以界面上明确标注了这一点，默认不用它。

**数量**：留空 = 全仓买入 / 全部卖出；也可手填，或用快捷按钮
（全部可用 / 一半 / 1 手 / 全部持仓）。

**撤单**：单笔撤或全部撤。

### 风控（下单前校验，不合格直接拒并说明原因）
| 规则 | 说明 |
|---|---|
| 资金不足 | 买入时按含滑点与手续费的总额校验，不够就拒 |
| 无持仓可卖 | 空仓时卖出直接拒 |
| 持仓不足 | 卖出量超过持有量直接拒 |
| **T+1** | A 股当日买入不能当日卖出。按**成交日**判断（不是信号日） |
| **整手** | A 股必须 100 股整数倍，自动向下取整 |
| 涨跌停 | 一字涨停买不进、一字跌停卖不出（在回放器里实现） |

### 自动交易
- 选一个策略（双均线 / RSI / 布林带 / MACD / 唐奇安），开关自动交易
- 启用时把当前目标仓位**对齐**，避免立刻误下单
- 只在**目标仓位变化**时下单，不重复挂单
- 走「下一根开盘」成交，与回测一致
- 开关状态持久化

### 行情推进
- 手动「刷新行情」：拉真实行情，新出现的 K 线会触发挂单成交并更新权益
- **自动刷新**：30 秒 / 1 分钟（默认）/ 5 分钟 / 关闭
- 页面不可见时不刷新；从后台切回来立刻补一次

### 界面
- **账户总览**：权益、收益率、可用现金、持仓数量/成本/市值、当前价、浮动盈亏、已实现盈亏、累计手续费、最大回撤、完成交易与胜率
- **权益曲线 / 价格**：双轴归一化，标出初始资金基准线，成交点用 ▲▼ 标在曲线上
- **明细 4 个标签页**：待成交（可直接撤单）/ 成交记录 / 全部委托（含被拒原因）/ 运行日志
- 操作反馈用 toast，失败原因原样展示（例如「资金不足（需 100,150.05，可用 1,000.00）」）

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/paper/meta` | 市场/策略/交易规则 + **常用标的与全量数量**（毫秒级） |
| GET | `/api/paper/sessions` | 账户列表 |
| POST | `/api/paper/create` | 建账户 `{market,symbol,interval,initial,label}` |
| GET | `/api/paper/:id` | 账户快照 |
| POST | `/api/paper/:id/refresh` | 拉行情并推进账户 |
| POST | `/api/paper/:id/order` | 下单 `{side,type,qty,reason}` |
| POST | `/api/paper/:id/cancel` | 撤单 `{order?}`（省略=全部撤） |
| POST | `/api/paper/:id/auto` | 自动交易 `{on,strategy?}` |
| POST | `/api/paper/:id/reset` | 重置 `{initial?}` |
| DELETE | `/api/paper/:id` | 删除 |
| GET | `/api/symbols/search?market=&q=&limit=` | **搜索标的**（代码 / 中文名模糊） |
| GET | `/api/symbols/list?market=&limit=` | 常用标的列表 |
| GET | `/api/symbols/counts` | 各市场标的数量 |

**架构**：Node 只做 HTTP 转发，账户状态由 Python 侧管理。
`server.mjs` → `paper_cli.py` / `symbols.py` → `paper_live.py`。
状态文件是唯一真相来源，每次调用都是「读状态 → 操作 → **原子**写回」
（`os.replace`），所以并发请求不会读到写了一半的文件。

## 标的目录（`quant/symbols.py`）

```
python quant/symbols.py --meta                          # 常用项 + 数量
python quant/symbols.py --search 宁德                    # 搜索
python quant/symbols.py --search ada --market crypto
python quant/symbols.py --list ashare --all --json       # 全量（8265 项）
python quant/symbols.py --resolve sz300750                # 解析名称
python quant/symbols.py --refresh                         # 强制重新枚举
python quant/symbols.py --selftest
```

### 数据源现状（实测）

| 接口 | 状态 |
|---|---|
| 新浪 K线 / 快照 | ✅ 任意代码，~130ms |
| 新浪批量快照 | ✅ 120 个/批，用于枚举 |
| Binance exchangeInfo | ✅ 511 个 USDT 对，但 **17MB / 10.4s，必须缓存** |
| 东方财富 clist（列表） | ❌ **已封** —— 曾成功 78ms 返回 5923 只，随后整个 IP 被拒 |
| 东方财富 push2his（K线） | ❌ **已封** |

> 注意「东财列表」和「东财K线」是**不同域名**（push2 vs push2his），
> 所以「能用」和「被封」都可能是对的 —— 要按具体端点判断。
> 最终 A 股全部改走新浪，不再依赖东财。

## ⚠️ 安全边界

**这是模拟盘，不是实盘。**

- 只读行情；代码里**没有任何交易接口的接入**
- 不持有 API Key；**没有下单能力**
- 不产生任何真实委托
- 所有成交只发生在内存与本地 JSON 文件里

## 开发过程中修掉的问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | `source`/`barAt` 只从 `self.series` 推导 | **重启后页头显示「源 —」、柱时间显示「—」**。修：改为独立字段并落盘 |
| 2 | `KeyError` 的 `str()` 自带引号 | 错误信息变成 `"'会话不存在：xxx'"`。修：取 `e.args[0]` |
| 3 | 非法市场参数把 argparse 的 usage 文本当错误返回 | 前端看到一大段命令行帮助。修：Node 侧先校验 |
| 4 | 测试代码写成 `tuple(Bar(...))` | `TypeError: 'Bar' object is not iterable`（自检抓到） |
| 5 | 默认初始资金 10 万买不起茅台一手（13.3 万） | 所有委托因「资金不足」被拒，看起来像策略没信号。修：A 股默认 100 万 |

## 已知限制

1. **只能做多** —— 没有做空（A 股本身也不支持散户做空，加密可以但没做）
2. **全仓进出** —— 没有仓位管理（凯利、固定比例、波动率目标都没做）
3. **没有真实撮合** —— 成交价就是开盘价 ± 滑点，不模拟盘口深度与部分成交
4. **多账户共用一个行情请求预算** —— 自动刷新频率高时可能触发数据源限流
5. **状态文件是明文 JSON** —— 本机单机演示用途；如果要多机共享需要换存储
6. **A 股数据源随时可能被封** —— 已备 3 个源（新浪 → 腾讯 → 东方财富），全挂就得换
